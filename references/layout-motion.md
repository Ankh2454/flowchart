# 布局与动效

## 先建立语义分区

架构图先整理“分区名称 → 职责 → 节点清单 → 区内关系 / 跨区关系”，再分配坐标。
分组依据内容：职责有上下依赖时按层；多个团队或产品平行协作时按业务域；过程有先后时按阶段。
同一级分区采用一致的划分依据，不把部门、技术组件和时间阶段随意混成几层。
用户给定的结构优先。缺少真实分层依据时采用平面关系图，不为了画色带发明中间层。

例如，输入确实包含接入认证、业务服务、异步执行和持久化时，可以归纳为
“接入与身份 / 业务编排 / 异步执行 / 数据存储”。这些名称与四层数量只是内容驱动的示例；
纯审批流程或核心辐射系统不照搬。视觉阅读顺序也不自动表示请求必须依次经过每一层。

- 每个分区有能概括职责的标题，不能只写“第一层 / 第二层”。标题单独占据顶栏或左侧标签栏。
- 分区底板包住多个相关节点及其标签，形成清楚的包含关系；它不是给单个节点加外卡。
- 分区内排布跟随局部拓扑：可以分支、汇聚、回环或并列，不强求每层一样多的节点或等宽等高。
- 跨域共享节点可独立成公共能力区，用真实连线接入。若为可读性重复绘制同一节点，标明同一实例的引用，
  不让读者误认为出现了多个独立服务。分组本身不代表网络、部署或权限隔离，除非输入明确说明。

## 由关系决定版式

| 关系 | 构图 | 特别留意 |
| --- | --- | --- |
| 单线流程 | 横向或纵向主轴 | 不强行加分支；长流程可分段 |
| 分支与汇聚 | 主轴 + 上下分支 | 条件贴近分叉；汇聚用不同输入锚点 |
| 分层架构 | 有标题的全宽浅色剪纸带纵向堆叠，层间留连接走廊 | 先看清层级，再看区内节点；不强制请求逐层经过 |
| 并行业务域 | 有标题的并列或分组剪纸区域 | 体现职责归属，不用上下位置暗示不存在的层级 |
| 核心与卫星 | 中心物件 + 辐射布局 | 标签不跟随节点旋转 |
| 生命周期 | 环形路径 + 外侧节点标签 | 方向持续一致，给条件留空 |
| 对比 | 对齐的两列或矩阵 | 并列不是流动，无关系时不画箭头 |

1440px 宽图的起点：画布边距约 64–80px，物件约 130–190px，节点之间留 60–110px
连接走廊。随内容调整画布，不固定五节点或横向比例。宽图在手机上可等比预览，
若用户主要用于手机，则另排纵版，不把等比缩小称作移动端可读。

## 分区尺寸与连线走廊

在 1440px 基准下，分区标题约 28–32px，明显高于说明文字。标题区可先留 48–64px，
底板内边距约 24–40px，区间留约 36–64px 走廊；多条跨区线或长标签需要进一步加宽。
分区高度由标题、节点及标签、局部回环和内边距相加得出，不先锁定等高色带再缩字塞内容。
同层节点少时可以缩窄区域或调整物件间距，不为填满区域新增节点或装饰。

先给每个分区预留标题与连线入口，再给节点分配物件矩形、标签矩形及运动包围盒。
区内连线尽量留在本区，跨区线走预留走廊或外侧，避开分区标题和说明。
跨区连线保留源节点、目标节点、方向及必要的载荷/条件标签；不能用分区序号代替真实依赖。
多条线可平行排布，但不能为了整齐合成一条不存在的公共总线；仅共享颜色不代表共享数据流。
箭头落在物件外轮廓附近，避免连接到说明文字。弯道半径统一，回流尽量走外圈。
反馈是实在的关系，不能一律画成表示弱关联的虚线。双向关系需要两个方向标记。
跨线能重排就重排；无法避免时用明确桥接，不能让交叉误读为汇合。

## 动画的语义

开始前用一句话写清载荷：文档、请求、订单、事件或任务。
用小纸片、票据、简洁圆点表达它；小载荷不放无法读清的文字。
纯拓扑或静态对比图不必强加流动。不要用动画编造真实系统没有的反馈。

每个关键物件选一个符合功能的动作：

| 物件 | 动作 | 建议幅度 |
| --- | --- | --- |
| 文档/输入 | 顶页轻抬、滑入 | 3–6px |
| 印章/处理器 | 压头下移、抽屉推进 | 6–12px |
| 队列 | 第一张票据向出口移动 | 4–8px |
| 存储 | 顶层落下或层间轻移 | 3–5px |
| 放大镜 | 在纸面小范围扫描 | 4–8px、2–5° |
| 完成标记 | 轻压实，再回稳 | scale 1–1.05 |

只动画功能部件，不让整个节点和标签一起漂浮。优先选择 2–4 处主要动作；多节点图
减少动作数。动作之间错开阶段，画面始终有稳定参照。
载荷以稳定速度流动，动作使用 ease-in-out；局部动作平时静止，在循环中的一段发生。
1440px 基准下可先以 80–140px/s 试播，再按展示尺寸调整。周期取 loop 的整数分之一，
不要让 150px 短线默认走满 6 秒（只有约 25px/s）。先测路径长度，再选择接近目标速度的
周期；长回环可走满一个 loop，短线常用 loop/4 或 loop/3。最终以播放可见性为准。

## 可录制的周期

- 默认全局 loop=6000ms；所有 CSS 动画时长整除它，infinite，延迟为 0 或负值。
- alternate/alternate-reverse 的完整周期是 duration×2；也要整除 loop。
- loop 两端保持相同视觉状态。载荷在端点淡出，防止从终点瞬移起点。
- 长短路径可选 loop、loop/2、loop/3 等速度档。过慢时缩短路径周期，不把微动幅度放大。
- `offset-position:0 0`；连线 d 与 offset-path 使用同一份坐标，在同一 transform 空间。
- 标签与流动部件分组，缩放/平移外层，动画内层，避免 CSS transform 覆盖 SVG transform。
- CSS 动画可被 document.getAnimations() 定格；不用 SMIL、JS 帧循环或随机运动。
- `prefers-reduced-motion` 下停止动画并隐藏载荷，保留完整静态关系。

默认的多个载荷表示持续流转，而不是一份文档在各分支同时出现。
若用户需要演示单个请求的因果时间线，按阶段安排载荷与节点动作，不用多个独立循环冒充。

## 验证实际导出

先缩到 50% 检查整图：在不读小字时能否看清主题、分区标题和主要跨区关系。
再恢复目标展示尺寸，检查节点归属、区内关系和跨区线是否可追踪。若只能看出几排图标，
先修正分区边界、标题或分组依据，不靠增加阴影和颜色补救。细节过密时拆成总览与分区详图，
总览说明合并范围并保留关键跨区关系，不默默删除例外或改变拓扑。
HTML 与 GIF 都要看。至少取开始、中间、末段三帧，确认载荷位移与动作实际存在。
比较 t=0 与 t=loop 的截图，检查循环接缝；文字抗锯齿的极少差异可容忍，几何位移不能。
确认 GIF 没录入暂停按钮，物件和投影没有被裁切，中文在最终显示尺寸下可读。
